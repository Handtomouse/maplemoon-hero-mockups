### Failed Audit (1)

**aria-hidden-focus** (score: 0, severity: serious, WCAG 2.1 4.1.2)

The mobile menu (`div.mobile-menu`) has `aria-hidden="true"` but contains focusable descendants (close button, all `<a>` links). When a keyboard user tabs through the page, focus enters the hidden menu's links even though they are invisible and announced as hidden by screen readers.

Failing element:
```html
<div class="mobile-menu" role="dialog" aria-modal="true"
     aria-label="Navigation menu" aria-hidden="true">
  <button class="menu-close" aria-label="Close menu">&times;</button>
  <a href="/shop/bars">Bars</a>
  <!-- ... 12 more focusable links -->
</div>
```

**Fix:** Add `tabindex="-1"` to all focusable children inside `.mobile-menu` when it is closed, and remove `tabindex="-1"` when opened. Alternatively, use `inert` attribute on the container when hidden:
```html
<div class="mobile-menu" role="dialog" aria-modal="true"
     aria-label="Navigation menu" aria-hidden="true" inert>
```

### Informational Warning

**aria-allowed-role** (minor): The `<label class="hamburger" role="button">` uses `role="button"` on a `<label>` element. This is technically not an allowed ARIA role for `<label>`. Replace with `<button>` element or remove the role.

## 2. Accessibility Audit

### 2.1 Accessibility Tree Structure

The a11y tree is well-structured:
- `RootWebArea` > `banner` (header with nav) > `main` (hero content)
- `h1` ("MapleMoon -- Choose your flavour") correctly present as `sr-only`
- Two `tablist` containers with correct `role="tablist"` and `aria-label`:
  - "Product category" (Bars / Moons / Bites / Elixirs)
  - "Flavour selector" (Pure Carob / Golden Coconut / Peppermint / Hazelnut)
- `aria-selected` toggles correctly on both tab groups
- CTA link exposed as standard link with text "SHOP PURE CAROB"

### 2.2 Focus Order

Tested via Tab key traversal. The focus order is:

1. Skip to content (correct)
2. Back to Gallery link
3. **Mobile menu close button** (PROBLEM -- inside `aria-hidden="true"`)
4. **Mobile menu links x12** (PROBLEM -- same issue)
5. Desktop nav: Our Story > Shop > Stockists > Recipes > Contact
6. Category tabs: Bars > Moons > Bites > Elixirs
7. Flavour pills (visible ones only -- `display:none` pills correctly skipped)
8. CTA button

**Issue:** Focus items 3-14 (13 elements) are inside the hidden mobile menu. On desktop, these are invisible but still receive keyboard focus. This is the same bug flagged by Lighthouse. It means a keyboard user must tab through 13 invisible elements before reaching the nav.

**Fix:** As above -- add `inert` to `.mobile-menu` when closed, or set `tabindex="-1"` on all its interactive children.

### 2.3 Keyboard Navigation Within Tabs

Arrow key navigation is implemented correctly:
- Left/Right arrows move between category tabs and auto-activate
- Left/Right/Up/Down arrows move between visible flavour pills and auto-activate
- Only visible pills participate in arrow key navigation (hidden pills filtered out)
- `focus-visible` outlines are defined (2px solid cream, 4px offset)

**Concern:** The WAI-ARIA tab pattern recommends that only the active tab should be in the tab sequence (tabindex="0"), with inactive tabs at tabindex="-1". Currently all tabs are in the natural tab order, meaning a user must tab through every category tab and every flavour pill rather than using arrow keys. This is functional but not the recommended pattern.

**Additional opacity-compounded failures:**

| Element | Effective Contrast | Result |
|---------|-------------------|--------|

### 3.2 Image Loading Strategy

| Image | `loading` attr | `fetchpriority` | Actually Loaded |
|-------|---------------|----------------|-----------------|
| maplemoon_logo.svg (x2) | eager | auto | Immediately |
| carob_wordmark.svg | (none) | auto | Immediately (preloaded) |
| bar_pure_carob.webp | **eager** | **high** | Immediately (correct -- hero image) |
| All other product images | lazy | auto | **Loaded anyway** (preloaded) |

**Issue:** The `<link rel="preload">` tags defeat `loading="lazy"`. The HTML preloads 8 images:
- `bar_pure_carob.webp` (needed)
- `carob_wordmark.svg` (needed)
- `bar_goji_coconut.webp`, `bar_hazelnut.webp`, `bar_peppermint.webp` (bars -- reasonable)
- `moon_pure_carob.webp` (WRONG -- this image is not used on the page; the default moon is `moon_hazelnut.webp`)
- `bite_coconut.webp` (category default -- reasonable)
- `elixir_plain.png` (713KB PNG -- should not be preloaded)

**Recommendations:**
1. Remove preload for `moon_pure_carob.webp` (not used)
2. Remove preload for `elixir_plain.png` (713KB, not the default view)
3. Convert `elixir_plain.png` (713KB) and `elixir_spiced.png` (965KB) to WebP -- these two PNGs account for **67% of total page weight**
4. Only preload the hero bar image; let other categories load lazily when selected

### 3.3 CLS (Cumulative Layout Shift) Risk

**Low risk.** The implementation handles this well:

- `.product-stack` is `position: relative` with fixed `height: 52vh` / `max-height: 520px` (desktop)
- Active image is `position: relative` (sets container size)
- All inactive images are `position: absolute` with `opacity: 0`
- Transition is `opacity 0.4s ease` only -- no dimension changes
- Active image toggles to `position: relative` which could cause a brief reflow if images have different aspect ratios

**Potential CLS edge case:** Bar images are 400x600 (2:3) while Moon/Bite images are 400x400 (1:1). When switching from Bars to Moons category, the active image changes aspect ratio, which will shift the layout below (tagline, pills, CTA). The stack height changes from ~489px to ~326px.

**Fix:** Set a fixed height on `.product-stack` that does not depend on the active image, or use `min-height` to prevent collapse.

**Shopify mapping:**

- Shopify products: `/products/pure-carob-bar`, `/products/hazelnut-moon`, etc.

The current `/shop/bars/pure-carob` structure does not map directly to Shopify's default routing. Two options:

1. **Product pages:** Rewrite CTAs to `/products/{handle}` (e.g., `/products/pure-carob-bar`). Simple, standard.
2. **Collection-filtered:** Use `/collections/bars/products/pure-carob-bar`. More aligned with current structure but verbose.

Recommendation: Use direct product URLs (`/products/{handle}`). The category filtering is already handled by the hero UI itself.
