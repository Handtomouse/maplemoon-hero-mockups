## Issues

### [1][BUG][P1] Dead CSS rules for .card-title in desktop media query
In `@media (min-width: 768px)`, three rules target `.card-title` classes that no longer exist (replaced by `.card-label` / `.card-answer`):
```css
.card-pod .card-title, .card-craft .card-title { font-size: 1.3rem; }
.card-shop .card-title { font-size: 1.2rem; }
```
**Fix:** Delete both dead rules from the desktop media query block.
**File:** hero_v9.html, desktop `@media (min-width: 768px)` block

### [2][BUG][P1] Progress dots .on-cream logic is inverted — dots invisible on Card 4
JS adds `.on-cream` class when scrolling to Card 4 (index 3). CSS `.on-cream .dot { background: var(--mm-navy); }` was correct when Card 4 had a cream background. Card 4 now has a dark photo background — navy dots on dark = invisible.
**Fix:** Remove the `.on-cream` CSS rule entirely and remove the `dotsContainer.classList.add/remove('on-cream')` logic from the JS scroll handler. Cream dots now work on all 4 dark-background cards.
**File:** hero_v9.html, CSS `.progress-dots.on-cream` + JS scroll IIFE

### [3][BUG][P1] JS breakpoint check uses window.innerWidth at load — no resize/orientation handling
```javascript
if (window.innerWidth >= 768) return;
```
Fires once at page load. On orientation change or browser resize, the dot-tracking script does not re-initialise.
**Fix:** Replace with matchMedia:
```javascript
var mq = window.matchMedia('(min-width: 768px)');
if (mq.matches) return;
```
This still runs once at load but is semantically correct and can be extended with `mq.addEventListener('change', ...)` if dynamic re-init is needed later.
**File:** hero_v9.html, second JS IIFE (scroll-dots block)

### [4][LAYOUT][P1] .card-content layout inconsistency — flex on Cards 3+4, block on Cards 1+2
Cards 3 and 4 use `display: flex; flex-direction: column; align-items: center; gap: 20px / 24px`. Cards 1 and 2 use block layout with manual `margin-top` on children. Results in inconsistent spacing across the 4 cards.
**Fix:** Standardise all 4 `.card-X .card-content` to `display: flex; flex-direction: column; align-items: center; gap: 8px;`. Remove `margin-top: 10px` from `.card-answer` and `margin-top: 12px` from `.card-pod .card-subtitle` and `.card-craft .card-subtitle`. Remove explicit gap from `.card-bar .card-content` and `.card-shop .card-content` (replaced by shared gap: 8px).
**Files:** All 4 card CSS blocks in hero_v9.html

### [5][STANDARDS][P2] Inline rgba() colour values in all card overlays — violates brand_kit rule
All 4 overlays use raw rgba():
- `.card-pod .card-overlay` → `rgba(58,42,26,0.4)`
- `.card-craft .card-overlay` → `rgba(30,50,80,0.45)`
- `.card-bar .card-overlay` → `rgba(30,20,10,0.35)`
- `.card-shop .card-overlay` → `rgba(20,30,50,0.4)`
**Fix:** Define as local CSS vars in the `:root` block at top of `<style>`:
```css
:root {
  --v9-overlay-pod:   rgba(58,42,26,0.50);
  --v9-overlay-craft: rgba(30,50,80,0.40);
  --v9-overlay-bar:   rgba(30,20,10,0.58);
  --v9-overlay-shop:  rgba(20,30,50,0.45);
}
```
Replace all rgba() literals in overlay rules with the new vars. Note: opacity values also updated per D20 issue [6].
**File:** hero_v9.html, `:root` block + all `.card-X .card-overlay { background: ... }` rules

### [7][A11Y][P2] .cta-btn missing :focus-visible style

### [8][PERF][P2] PNG format used for photographic CSS backgrounds
`hero_carob_bar_hand.png` and `hero_moons_lifestyle.png` are PNG files used as CSS `background-image`. PNG is lossless — for photographs, JPEG or WebP is significantly smaller.
**Fix:** 🔴 REVIEW — Convert via:
```bash
sips -s format jpeg assets/hero_shots/hero_carob_bar_hand.png --out assets/hero_shots/hero_carob_bar_hand.jpg
sips -s format jpeg assets/hero_shots/hero_moons_lifestyle.png --out assets/hero_shots/hero_moons_lifestyle.jpg
```
Update both CSS `background-image` references from `.png` to `.jpg`.
**File:** hero_v9.html, `.card-bar .card-bg` and `.card-shop .card-bg` background-image URLs

### [13][A11Y][P3] .mobile-menu .menu-nav a at opacity 0.6 may fail WCAG AA contrast
`color: var(--mm-navy); opacity: 0.6` on cream background. --mm-navy (#1E4366) at 60% opacity on cream reduces effective contrast ratio — may fall below the 4.5:1 WCAG AA threshold for normal-sized text.
**Fix:** Change `opacity: 0.6` to `opacity: 0.75` to improve contrast while retaining the visual de-emphasis.
**File:** hero_v9.html, `.mobile-menu .menu-nav a`

### [14][CODE][P3] .card-content padding: 0 32px may cause label wrap at small desktop widths
At 20vw collapsed width on a 1024px screen = 204px column. Padding 0 32px each side leaves 140px usable. "Where:" at 2.6rem ≈ 124px — borderline. At 1.4rem (collapsed state after D20 fix) this is resolved, but the base resting state at 1024px could still wrap.
**Fix:** Change `padding: 0 32px` to `padding: 0 clamp(16px, 4%, 32px)` on all 4 `.card-X .card-content` rules so padding scales with viewport.

### [15][CODE][P3] swipe-hint bottom: 72px may overlap card-content text on short screens
`.swipe-hint` is `position: absolute; bottom: 72px`. Progress dots are at `bottom: 32px`. On iPhone SE (667px height) with tall card-content text block, the swipe hint may visually collide with subtitle text.
**Fix:** Change `bottom: 72px` to `bottom: 80px` on `.swipe-hint` for a consistent clear gap above the 32px progress dots.
**File:** hero_v9.html, `.swipe-hint` CSS rule
